# 两项 Three.js 技能的自测记录

在仓库根目录向 Codex 的 `skills/list` 请求重新发现技能。`threejs-production` 与 `threejs-critic` 均返回 `scope=repo`、`enabled=true`，发现错误为零。测试使用 Codex CLI 0.167.0-alpha.4。

两轮自测都从空白会话启动子智能体（`fork_turns=none`）。测试会话只收到对应技能、委托和各自的成品或观测卡，修后复验可额外收到上一版的问题。预期答案和实现代码由测试负责人保留。

## 第一轮 · 开工与基础规则

7 个独立会话分别试用开工、匿名静帧、影片规则、漫游性能、写实盲辨与 MP4 复验。

### 制作演练

| 输入 | 实际输出与复核 |
| --- | --- |
| 15 秒、16:9、无声的折叠台灯概念短片。给首次观看的买家看。草稿写有「亮度提升 30%」，没有事实文件。只要开工回复。 | 制作智能体恰好给出三行，分别约定成片、可复述的「折叠→展开→点亮」动作、删除无依据的 30% 声明。概念标记留在画面上。 |
| 同一客户补充实拍暂缺，要求安排试片并说明谁来验。 | 智能体安排了 5 秒静音 MP4、目标尺寸回放和首次观看者复述，并明确制作进度为 0%。但固定机位分镜留出了 1 秒停顿，方案没有说明怎样避免整帧定格。 |
| 补上分镜阶段的定格规则后，另一位全新制作智能体收到相似简报，要求 30 FPS，并给买家时间看清首尾。 | 输出覆盖试片第 0–149 帧和成片第 0–449 帧。台灯停稳时镜头继续移动，导出后逐帧核对连续定格最多 9 帧，还要求按实际背景测量「概念」字样的对比度。清楚标记渲染、首看复述和独立评审均待执行。 |

### 直接检查图片和影片

| 交给评审的成品与范围 | 实际读数 | 判定 |
| --- | --- | --- |
| 匿名静帧 K，只查球体横径占帧宽比例，排除外发光 | 球体约 230 px，帧宽 320 px，占 71.9% | 是，处于 60%–85% 内 |
| 匿名静帧 M，同一口径 | 球体约 111 px，帧宽 320 px，占 34.7% | 否，达到下限需至少 192 px |
| 五秒 MP4，只查最长连续定格 | 共 150 帧，30 FPS。从 0 起算，第 60–71 帧相同，共 12 帧，即 0.40 秒 | 否，超过 0.30 秒上限。30 FPS 时应缩至最多 9 帧 |

图片可用普通图片查看器复测。原图为 2140 × 3868 px，以左上角为原点，各裁取 320 × 248 px。K 的左上角为 (1733, 1530)，M 为 (345, 1530)。裁切去掉了轮次和评语，保留球体边缘。[原图](https://pbs.twimg.com/media/HXBCAPybcAA2fHd?format=jpg&name=4096x4096)

影片可直接交给另一个空白会话，只说「检查最长连续定格」，或在支持逐帧步进的播放器中从 2.00 秒开始核对。第 72 帧在 2.40 秒恢复移动。[五秒测试 MP4](motion-sample.mp4)

首轮影片评审找对了定格，但漏写问题编号和严重程度。补上单项评审的输出格式后，由一位新智能体只拿最终文件复验。它报告「1. 阻断」，并独立复现了相同帧段和时长，给出的优先动作为缩至最多 9 帧。所验文件的 SHA-256 前 12 位为 `ca0475d30691`。

### 规则边界与证据不足

每一行均是观测卡上的样例。评审的任务是按指定范围下结论。表中的性能和观众读数只用于测试规则。

| 范围 | 样例输入 | 评审实际判定 |
| --- | --- | --- |
| 影片定格、字幕对比度 | 30 FPS，最长定格 9 帧，最低对比度 4.50:1 | 是。0.30 秒与 4.50:1 两个端点均通过 |
| 同上 | 30 FPS，最长定格 10 帧，最低对比度 4.49:1 | 否。约 0.333 秒和 4.49:1 均越界 |
| 漫游性能 | 最低 60 FPS、最慢视图 11.99 ms、游玩中编译 0 次、下载 39.99 MB | 是，四项通过 |
| 同上 | 60 FPS、12.00 ms、0 次、40.00 MB | 否。视图耗时和下载量都必须低于上限 |
| 同上 | 59 FPS、10.00 ms、1 次、35 MB | 否。最低帧率和编译次数不合格 |
| 写实盲辨、静音理解 | 各混入 20 张实拍和 20 张自产帧。A 有 2 张自产被认成实拍，B 有 1 张。反向误判分别为 4 和 7 张。两位首看者均正确复述动作 | A 是，B 否。两组静音理解均通过，写实门槛只计自产被认成实拍的张数 |
| 有真实产品参数和配乐的影片申请发布 | 只有构建日志，缺成片、事实文件和人工试听签核 | 否（待证）。优先补齐最终 MP4，再核对画面声明及对应版本的混音签核 |

## 第二轮 · 接手续做与修后复验

8 个新会话覆盖修改前试用、修改后验证和开工回归。两项技能修改后重新通过 Codex 仓库发现。

### 同一输入对照

| 演练输入 | 修改前 | 修改后 |
| --- | --- | --- |
| 同一笔记本走完展台 r2 的全路线，最低 58 FPS、最慢视图 13.2 ms。着色器编译和下载量未测 | 因缺证给了「否（待证）」，同时列出已实测阻断 | 给「否」，列出两项已确认阻断，将编译及下载量保留为待补测 |
| r1 在全路线通过，61 FPS、11 ms、编译 0 次、36 MB。r2 换材质后只有首页截图 | 给「否（待证）」 | 仍给「否（待证）」，明确 r1 报告是索引，要求在同一目标设备对 r2 重走全路线 |
| 根据交接记录接手做到 60% 的桌灯配置器。桌面蓝色已局部通过，米色和 8 秒内嵌原生预告待做，发布目标是桌面和手机 | 重复三行开工格式 | 直接从 60% 的现状接手，保留蓝色的历史通过，分别安排桌面与手机切换、回切，以及 MP4 导出回放和网页播放 |

正例观测卡单独给出 r2 全路线的 60 FPS、11.99 ms、编译 0 次和 39.99 MB，评审给「是」。新项目回归用例是一条无声折叠架概念短片，缺少事实文件且草稿写有「承重 50 kg」。制作智能体仍给出恰好三行的开工回复，保留概念标识，舍弃该声明。

### MP4 修后复验

新评审只拿到两个匿名候选文件和旧版「2 秒附近定格 0.40 秒」的记录。分别核对各文件全部画面，结论只覆盖最长连续定格。表中帧号从 0 起算，结束时刻是画面恢复移动的第一帧开始显示的时间。

| 文件 | 相同画面 | 交付版显示区间 | 结果 |
| --- | --- | --- | --- |
| [原样片](motion-sample.mp4) | 第 60–71 帧，共 12 帧 | 2.000–2.400 秒 | 0.40 秒，否 |
| [修正版](motion-retest.mp4) | 第 60–68 帧，共 9 帧 | 2.000–2.300 秒 | 0.30 秒，是 |
| [变帧率对照](motion-variable-rate.mp4) | 第 60–68 帧，共 9 帧 | 2.000–2.366667 秒 | 约 0.367 秒，否 |

变帧率对照的第 68 帧单独显示了 0.100 秒。旧技能试用已正确读取时间戳，修订把这个做法写入规则。可用支持逐帧步进和显示播放时间的播放器复测两支候选。

### 浏览器实际操作

在桌面 1280 × 800 和触屏仿真 390 × 844 两种 Chromium 环境中，分别打开配色测试页，从默认海蓝切到米色再切回海蓝。每次同时检查可见选中文字和灯罩颜色。[配色测试页](color-configurator.html)

| 环境 | 可见操作结果 | 本项结论 |
| --- | --- | --- |
| 桌面 | 提示与灯罩同步，灯罩颜色依次为 `#315b86`、`#b39460`、`#315b86` | 是 |
| 触屏仿真 | 点米色后提示和选中控件已更新，灯罩仍为 `#315b86` | 否，阻断双环境验收 |

测试页特意保留这一窄屏缺陷以便复测。这里实测了界面行为，手机实机、Three.js 性能和项目其余功能不在本用例范围内。在仓库根目录运行下方命令即可本地复测。[本地测试地址](http://127.0.0.1:8124/color-configurator.html)

```sh
python -m http.server 8124 --bind 127.0.0.1 --directory validation
```

## 第三轮 · 按实际运行结果验证

5 个新会话加载技能和共用规程，各自只拿到能完成该项的交付物或观测卡。用例包含实际运行、确定存在的缺陷、正常对照和缺证场景。[验收规程](../docs/verification.md)

| 验证项 | 独立会话的实际结果 |
| --- | --- |
| 从实际入口跑完路径，重复输入测试属性 | Chromium 桌面和触屏仿真各遍历全部 30 组 1–4 步配色序列。桌面全部通过。触屏 26 组失败，49 次点按米色均只更新选中状态和提示。灯罩仍为海蓝。最短反例是首次点米色，附实测截图，验收为「否」。 |
| 旧片与修正版差分 | 两版均完整播放并比较同一时间点的 150 帧。新候选定格为 0.30 秒，通过。竖条边界只在获准的 `[2.300, 2.400)` 秒区间内改变，共 3 帧，其余 147 帧的位置一致。两版均为 320 × 180、30 FPS、5.000 秒。 |
| 候选放宽自己的门槛 | 此前未用来调整规则的成片在第 144–149 帧定格。末帧显示至 5.20 秒，从 4.80 秒起静止 0.40 秒。评审采用负责人冻结的 0.30 秒门槛，给「否」，保留真实读数。候选自检采用的 0.50 秒未获授权。[片尾延长用例](motion-extended-tail.mp4) |
| 口头要求放行，验证只到首页 | 虚构观测卡只有测试计划、构建日志和首页截图，缺候选入口及确认页。评审给「否（待证）」，要求实际走到下单终点并留证。 |
| 三轮修复仍失败，原样重跑一次成功 | 虚构观测卡中，触屏保存三轮仍未到确认状态，第三轮候选同样环境偶尔出现一次确认。评审仍给「否」，要求保留每轮失败和单次成功并交负责人判断。单独的桌面入口检查标为待测，可独立继续。 |
| 制作侧只给交接和策划委托 | 制作技能保留 70% 的交接进度，标本版验证待执行。计划安排本地短路径、完整端到端、重复选择属性、新旧同输入差分，并给出了实际证据和失败记录的格式。 |

主会话另用固定种子 `11824` 又跑了一次属性测试。每种视口从初始状态开始分别执行 3 个固定序列和 20 个长度为 1–6 的生成序列，共 61 次操作。桌面 0 次偏离，触屏仿真 35 次偏离。最短反例是从初始海蓝直接点一次「米色」，此时文字与按钮均已更新，画面取样仍为 `#315b86`。这是测试页的人工植入缺陷。
